## Industry-neutral deployment assessment

The current organization model represents one service provider with many monitored customers. An enterprise can use one customer with the same explicit-scope contract. Separate independent provider tenants require an explicit ownership/login architecture decision; customer selection alone is not a provider-isolation model. No actual customer topology is asserted.

| Dimension | Existing evidence / suitability | Alternatives and required decision / gate |
|---|---|---|
| Deployment topology and HA | Modular API, worker, PostgreSQL, remote agent/collector identities | Single-site controlled development exists; choose isolated single-enterprise or provider-operated multi-customer deployment. Multi-replica/failure-domain evidence remains required. |
| Trust zones and private connectivity | TLS ingress, authenticated ingestion, read-only platform methods | Choose agent-outbound pull versus explicitly approved private connectivity; define ingress/API/DB/collector/provider zones. No public database or implicit network trust. |
| Authentication/authorization | Existing sessions, direct/inherited roles, boundaries and delegation | Decide enterprise identity-provider integration and emergency access operations; preserve server-side resolver and no implicit grants. |
| Canonical resources and ownership | Native resource identities, resource control plane, fenced collection units | Shared VMware/cloud/network infrastructure needs explicit attribution or quarantine. Do not register duplicate customer resources to evade a sharing decision. |
| MSP and internal service ownership | Customers separate from departments; audited incident assignment | Decide customer-safe service ownership and escalation routing. Department names confer no customer authority. |
| Windows/Linux and VMware/private cloud | Agent package/source and existing VM monitoring; Windows build/UAT not certified | Select OS/build, service privileges, CA path, host install/upgrade/rollback and private connectivity tests separately. VMware-specific inventory/telemetry capabilities require verified provider contracts. |
| AWS/Azure/cloud-native | Existing Glue/ADF platform contracts and scope protections | Approve sandbox identities/regions/subscriptions and platform-specific evidence; service API success does not establish native workload health. |
| Kubernetes/managed containers | Existing agent/collector patterns; EKS inventory is distinct from in-cluster access | Decide in-cluster least-privilege service account versus external discovery; verify namespace/customer attribution, ephemeral identities and target network policy. |
| Data pipelines and ETL | Nine native adapter families, immutable execution evidence | Exact build/method certification required; no execution/start/restart/cancel/rerun controls. |
| APIs/distributed applications | Approved HTTPS probes; OTLP logs/metrics/traces | Confirm service identity, trace linkage, coverage and synthetic-versus-business-health semantics before SLO claims. |
| Telemetry/storage/durability | Bounded OTLP ingestion, durable agent buffers, PostgreSQL evidence | Agree formats, queue/disk limits, backpressure and recovery guarantees; PostgreSQL must not become an unbounded raw telemetry sink. |
| Coverage, clocks and incident correlation | Coverage-aware schedules; timestamps; evidence-based native incidents | Define missing/stale/skew contracts and common-root evidence. Correlation never becomes causal or downstream-restoration proof automatically. |
| SLO governance | Thresholds/reports exist; dedicated provenance/policy not located | Recover approved SLO definitions; choose windows, denominator, missing-data and policy-change semantics. |
| HA, backup, recovery, upgrade | Controlled restore and config rollback tools | Agree RTO/RPO, encryption, independent backup location, component compatibility and recovery drills. |
| Operational workflows | Compact six-page console and backend decision confirmation | Independent operator UAT, handover, routing and escalation ownership required. |
| Data protection/retention/residency | Secret redaction, legal holds, immutable audit and retention bounds | Approve region/residency, sensitive-field handling, archival attestation and deletion exceptions; evidence holds take precedence. |
