# Future witnessed read-only connection runbook

This is a **preparation procedure**; no step involving a live Pentaho host was performed in Sprint 14. Follow [credentials/network prerequisites](CREDENTIAL_AND_NETWORK_PREREQUISITES.md) and the [RT matrix](RT001_RT020_ACCEPTANCE_MATRIX.md). An owner authorization must name **each** target, route, method and live test group; a general Sprint 14 instruction does not authorize a connection.

1. Record target/customer, exact product/build/OS/Java, approved observation method, read-only principal/secret reference, endpoint/path allowlist, evidence store, change window and independent witness. If any is missing, mark the case **NOT RUN/BLOCKED prerequisite**; do not probe by guessing.
2. Confirm local host/CIDR policy, TLS chain, DNS pinning, source generation/fence, legal holds and customer scope. Test denied paths with controlled fixtures before a live request. Never disable certificate verification or widen ALL customer authority.
3. For Kitchen/Pan, review installed documentation and executable hash; observe already-running process metadata/native logs only through the approved agent. **Do not invoke Kitchen or Pan with job/transformation paths, even as a “test.”** Any help/version command needs separate explicit authorization as non-executing on that build.
4. For Server, obtain the build's published read-only repository/scheduler/history interface and privilege map. No generic Server endpoint is assumed. Distinguish scheduler trigger from native execution result; if only trigger/history summaries exist, record UNKNOWN outcome and capability limitation.
5. For Carte, use only approved HTTPS GET status paths: `/kettle/status/`, `/kettle/jobStatus/`, `/kettle/transStatus/`, subject to installed-build documentation. Never issue start/stop/remove/control requests. Preserve server/restart epoch, native ID and bounded response hash; treat inventory as advisory and a missing native result/error count as UNKNOWN. Do not certify legacy Carte `Finished` without `nr_errors` until its located unsafe default is corrected and reviewed.
6. Capture one case at a time: expected vs observed native evidence, customer/resource/source/method/generation, timestamps with timezone, build/reader version, hash, completeness, actor and independent witness. Separate process exit, schedule state, native execution result, monitoring health and incident state.
7. Stop on certificate/auth failure, unexpected endpoint/schema, ambiguous identity, contradictory evidence, restart epoch change, source fence loss, unsafe output or any apparent write capability. Quarantine ambiguous claims and retain the last defensible projection. Never “fix” a failure by running an ETL workload.
8. Only after a separately approved review may evidence change a method's runtime verification state. A green HTTP status, fixture, static profile or mock test remains insufficient. Preserve blocked/failed/NOT RUN cases with exact reason and no waiver-by-assumption.

The runbook is monitoring-only. No Pentaho start, rerun, restart, cancel, repair, repository edit, schedule edit, real source activation or live connection occurred in this sprint.
