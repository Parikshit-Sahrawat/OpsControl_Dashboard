# Bounded Pentaho adapter safety inspection

Inspection covered [R1 observation normalization](../../../../backend/app/pipeline_adapters/pentaho_observations.py), [R1 Carte reader](../../../../backend/app/pipeline_adapters/pentaho_carte.py), [legacy Carte status reader](../../../../backend/app/worker/pentaho_status.py), [adapter registry](../../../../backend/app/pipeline_adapters/__init__.py), [capability declarations](../../../../backend/app/pipeline_adapters/pentaho_contracts.py), [collection bridge](../../../../backend/app/data_pipelines/bridge.py), [egress](../../../../backend/app/worker/egress.py) and [credential resolution](../../../../backend/app/worker/credentials.py). This is static/code-fixture evidence, not a network or installed-build test.

| Finding | Code and controlled observation | Consequence / disposition |
|---|---|---|
| **S14-01 Legacy Carte missing error count can become success — P0 safety blocker** | `parse_carte_status` defaults absent `.//nr_errors` to string `0`, then maps `Finished` with zero errors to `SUCCESS`. Controlled XML `<jobstatus><id>r1</id><status_desc>Finished</status_desc></jobstatus>` yielded **legacy `SUCCESS`**, while R1 `parse_status` yielded **`UNKNOWN`**. | Missing native result evidence must not be treated as verified success. Do not certify or use this legacy projection for witnessed success. Separate narrowly scoped runtime correction/review is required before legacy live acceptance; no runtime code changed in Sprint 14. |
| S14-02 Fixed R1 read paths and transport boundary | R1 reader restricts GET to `/kettle/status/`, `/kettle/jobStatus/`, `/kettle/transStatus/`; local and configured egress host/CIDR must agree; DNS/IP is checked, HTTPS/TLS required, credentials via reference. Existing test denies `/kettle/startJob/`. | Code-level read-only boundary passes controlled tests. Actual build path/schema, account privilege, CA and private route remain unknown. No start/stop/remove path was called. |
| S14-03 CLI and Server do not have universal live reader | R1 normalizes authenticated CLI/Server observations; `Pentaho.collect` routes non-Carte contexts to unsupported capability rather than fabricating a Server endpoint or launching Kitchen/Pan. Search of Pentaho adapter path found no workload `subprocess` launcher. | Real agent observation producer and exact-build Server read interface are partial/unknown. Do not use CLI help or process execution without separately explicit non-executing authorization. |
| S14-04 Connectivity and status are not certification | R1 catalogue and batch evidence set `runtime_verified=False`; `normalize_observation` sets `runtime_certified=False`; `PROCESS_EXITED` with code `0` remains UNKNOWN; Server repository/scheduler claims do not assert native execution success. Carte XML `Finished` plus an error count can normalize to a source claim, but still is not installed-build certification. | HTTP 200, process exit, scheduler trigger, catalogue or `runtime_certified=False` fact cannot establish verified native health. Require native evidence, current source/reader generation and independent review. |
| S14-05 Version format is not build proof | Context rejects `unknown`, `10.2.x`, `11.0.x` and unsupported fields; the exact-build-shaped string in unit fixtures is synthetic. Candidate list contains several families only. | No family or fixture string becomes an installed-build compatibility claim. Record actual product/build/OS/Java and per-method evidence. |
| S14-06 Identity and evidence protections | R1 scopes customer/authority/environment/workload/native ID and Carte restart epoch or CLI host/start epoch; XML bounded to 64 KiB and rejects DTD/entities; raw CLI argv is reduced to count/hash; retry and outcome proofs remain separate. | Controlled protections exist. Exact native IDs, epoch source, XML/log schema, sensitive fields, timezone precision and external scheduler authority need a witnessed build. |

The legacy path also uses `outcome=SUCCESS` for a successful inventory transport even when that value is not an execution result. Reviewers must keep transport/collection state separate from execution outcome. S14-01 is a reproducible **code-level defect**, not a claim that a real Pentaho installation produced the sample; it is retained as an acceptance blocker rather than silently fixed in this preparation sprint. No ETL workload or live endpoint was accessed.
