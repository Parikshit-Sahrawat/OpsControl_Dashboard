# Pentaho method and installed-build compatibility boundary

[ARCH-ETL-001 §4](../../../architecture/ARCH_ETL_001_V16.md) requires exact-build, method-specific capability verification. [Contract declarations](../../../../backend/app/pipeline_adapters/pentaho_contracts.py) list version families `8.3`, `9.3`, `9.4`, `10.2.x`, `11.0.x` as **candidates only**; none is a tested or certified installed build. The repository has no Sprint 14 product/build, Java, OS, host or provider response to enter here. Do not transfer results between releases or infer an endpoint from a catalogue entry.

| Method | Located implementation / documented candidate | Runtime verification | Supported installed interface | Decision required before live test |
|---|---|---|---|---|
| Kitchen/Pan via Agent | [Observation normalizer](../../../../backend/app/pipeline_adapters/pentaho_observations.py) binds host/start epoch, executable hash, invocation and native result; process exit alone remains UNKNOWN. Contract calls producer status **PARTIAL**. | **NOT RUN** | **UNKNOWN**; no arbitrary Windows/Linux producer or workload launcher certified. | Approved installed executable hashes, process/log observation source, OS/Java/build, safe metadata access and scheduler authority. |
| Pentaho Server | Authenticated [observation normalization](../../../../backend/app/pipeline_adapters/pentaho_observations.py) separates repository, scheduler and execution history. No universal Server network endpoint is registered. | **NOT RUN** | **UNKNOWN**; Server installation and read-only API/export surfaces unprovided. | Exact documented read-only endpoints/exports, account privileges, native IDs and history granularity for that build. |
| Carte R1 | [R1 reader](../../../../backend/app/pipeline_adapters/pentaho_carte.py) restricts TLS GET to three status paths, scopes restart epoch, treats running inventory as advisory and does not self-certify. | **NOT RUN** | **UNKNOWN**; path presence and XML schema depend on installed build. | Verify exact GET path/auth/XML/status semantics, epoch source, log/step availability and privacy controls. |
| Carte legacy | [Legacy status reader](../../../../backend/app/worker/pentaho_status.py) is GET-only with TLS/egress checks, but defaults absent `nr_errors` to zero. A controlled fixture demonstrated `Finished` without `nr_errors` becomes `SUCCESS`. | **NOT RUN**; **SAFETY BLOCKER for success certification** | **UNKNOWN**; never accept this projection as native success when error count is absent. | Separately authorize a scoped correction and regression before any witnessed legacy success decision; use R1 conservative semantics where eligible. |

Across all methods, [profile evidence](../../../../backend/app/data_pipelines/service.py) and [R1 contract](../../../../backend/app/pipeline_adapters/pentaho_contracts.py) separate documented declarations, runtime verification and UNKNOWN. Exact-build strings in fixtures, such as `10.2.0.0-222`, are **synthetic** and not installation evidence. `HTTP 200`, a process exit code `0`, a scheduled trigger or a populated catalogue must never be promoted to verified ETL success. `SUCCESS_AFTER_RETRY` requires verified native/scheduler retry identity; manual reruns remain separate recovery executions. The eight non-Pentaho adapter families remain in the existing shared registry and were not changed.
