# Provider-operated deployment trust model

Deployment owner: one monitoring-service provider (GOV-03). External customers are Resource Management Organizations; provider employees belong to Access Management Departments. Multiple independent providers in one installation are outside the initial model. Approved responsibilities below are from [owner decisions](APPROVED_OWNER_DECISIONS.md); located code is linked where possible. Every target-network/CA statement remains **UNVERIFIED_DEPLOYMENT** until an approved environment is tested.

| Boundary | Trust owner | Authentication and authorization | Transport and credential lifecycle | Failure behavior, audit/evidence | Unverified deployment assumption |
|---|---|---|---|---|---|
| Customer resource → agent/read-only provider adapter | Provider integration/agent team with customer-approved access | Customer/resource/method-specific read authority; verified native identity; no ETL control | Approved local process/HTTPS/file path or private route; source secrets referenced, not exposed | Adapter failures and incomplete coverage remain UNKNOWN/INCOMPLETE; native evidence retained and fenced | Actual host privilege, provider ACL, private route, Windows/Linux and installed-build behavior |
| Agent → collector control | Provider deployment team | One agent/worker identity bound to collector and customer; [backend/app/telemetry/api.py](../../../../backend/app/telemetry/api.py) rechecks enabled credentials and source | Bearer digest with bounded old-token overlap; configuration checksums; TLS required in target path | Revoked/disabled identity denied; receipt and config revision retained | Production CA issuance, expiry, revocation, mutual TLS and agent fleet rollout |
| Collector method → canonical source owner | Provider collection team | Method ID, source generation, one active fenced owner; [backend/app/data_pipelines/models.py](../../../../backend/app/data_pipelines/models.py) and [backend/app/data_pipelines/runtime.py](../../../../backend/app/data_pipelines/runtime.py) | Provider-controlled worker/collector transport | Stale fence cannot commit evidence/checkpoint; held backlog remains held | Shared cross-customer attribution and physically shared collection unit policy |
| Collector/agent → ingestion API | Provider API/security team | Agent credential; locked collector/agent/worker recheck; approved method/signal IDs; [backend/app/telemetry/ingestion.py](../../../../backend/app/telemetry/ingestion.py) | TLS target boundary; bounded 2 MiB envelope and expanded body | Unknown/contradictory method ID rejected; missing method ID has explicit legacy compatibility; duplicate receipt/checkpoint control | Network ingress/firewall/CNI, test/production CA and loss/backpressure under outage |
| Ingestion → processing workers | Provider operations team | Internal worker identity and source lease/generation authority | Controlled internal service route and DB credentials | Bounded input/retry, no unauthorized replay, audit/checkpoint and failure diagnosis | Multi-replica failure, restart durability and telemetry continuity on target topology |
| Workers/API → PostgreSQL and immutable evidence | Provider DB/security team | Runtime DB roles, row/customer scopes, legal holds, audited decisions | Private TLS/credential boundary as deployment target; encrypted backup required | Existing transaction/fence/audit guards; restore and PITR targets are policy only | Target encryption, WAL archive, RPO/RTO, capacity and independent backup site |
| Employee browser/API → scoped data/actions | Provider identity/access team | Active session, direct/inherited roles, LIMIT/DENY, explicit one/several/ALL, separate mutation permissions; [backend/app/security/http.py](../../../../backend/app/security/http.py) | HTTPS ingress, session expiry/revocation | Missing scope yields empty set; 401/403/404 and audit; customer switching invalidates sensitive state | Real SSO, ingress proxy trust, browser/network policy and independent penetration review |
| Incident/outbox → external notification destination | Provider notification team and approved customer destination owner | Scoped incident/alert policy and credential reference, customer-safe routing | HTTPS/SMTP TLS per approved destination; bounded retry/fenced claim | Provider failure does not mutate ETL outcome; delivery receipts/errors retained | Actual provider ACL, recipient correctness, delivery idempotency and escalation-window contract |

Trust zones: customer assets/network; provider agent/collector or approved external adapter; private ingestion/API/worker zone; restricted PostgreSQL/backup zone; provider employee access; separately authorized notification egress. The same backend may host multiple processes, but the trust checks remain independent. A host/IP/HTTP success is not native workload success or verified monitoring health.

GOV-06 assigns CA, identity renewal, revocation and network access to the provider deployment team. Sprint 12 uses no real CA/network and changes no deployment configuration. [Threat scenarios](THREAT_MODEL.md) and [test matrix](TEST_MATRIX.md) identify the unverified boundaries.
