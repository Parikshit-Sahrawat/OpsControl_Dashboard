# Bounded controlled recovery plan

Authority: [GOV-07](../sprint12/APPROVED_OWNER_DECISIONS.md) sets configurable initial targets, while the [existing backup utility](../../../../backend/scripts/database_backup.py), [owned V1.6 harness](../../../../scripts/v16-acceptance.py), [pipeline ownership tests](../../../../backend/tests/test_pipeline_ownership_v16.py) and [new probe](../../../../backend/scripts/sprint13_recovery_probe.py) define the tested workflow. This plan was chosen before edits; it avoids shared volumes and native workloads.

1. Gate execution to the harness's `ENVIRONMENT=test`, `OPSCONTROL_V16_ACCEPTANCE=1`, loopback database and random `opscontrol-v16-*` Docker container. Create a private temporary directory and libpq service file; the harness removes its owned container and volumes in `finally`.
2. Seed two synthetic Organizations, one provider employee and role, A allow/B deny customer grants, a DataSource/Collector/CollectorMethod, one fenced PipelineSource, historical PipelineEvidence, one synthetic JobOrderHistory with UNKNOWN status, an OperationalIncident/activity, audit event and active LEGAL hold. These are controlled fixtures, not native Pentaho evidence.
3. Snapshot critical IDs and field projections, current effective access and 14 selected table counts. Measure source database size. Use the existing utility to write a private PostgreSQL custom archive plus SHA-256 manifest; confirm `pg_restore --list` can read it.
4. Create a second **empty database inside the same disposable container**, restore using the utility's checksum and empty-target guard, then compare the same deterministic projections and counts. Attempt cross-customer pipeline-evidence FK and duplicate evidence-identity inserts; both must fail without changing the restored data.
5. On the restored database, run `alembic check` and attempt a known unsafe populated downgrade to `0031_in_app_notifications`. The preservation guard must refuse; snapshot remains identical. The outer harness also validates its populated V1.5 upgrade, schema drift and empty downgrade/upgrade path.
6. On the restored data, verify the originator cannot release the LEGAL hold. Run ordinary cleanup; held 40-day evidence and the hold must remain. This does not authorize permanent deletion, alter safe retirement semantics or simulate an administrator bypassing database protections.
7. Copy the archive, alter it and keep the original manifest. Check restore rejects the copy before it can modify the target. Record monotonic backup/restore duration and physical sizes; report no production RPO/RTO inference.

Exit: label REC-01–06 individually PASS/FAIL/BLOCKED/NOT RUN, keep only sanitized JSON results under `/tmp`, inspect the report, then delete the owned container and private archive/credential files. Do not use this as proof of encryption, off-site retention, WAL/PITR, actual failure-domain recovery or RT-001–RT-020.
