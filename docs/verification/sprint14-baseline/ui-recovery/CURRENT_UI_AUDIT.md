The navigation is a flat list from [`TopNav.jsx`](../../../../frontend/src/components/TopNav.jsx). `App.jsx` holds the primary `active` page in React state; pipeline tabs alone use `#/pipelines/{key}`. Existing sidebar behavior includes a 240 px expanded / 72 px collapsed state, a top toggle, persisted preference, labels/tooltips and `aria-current`. At narrow widths it becomes a horizontally scrolling top strip. The mobile captures show entries extending outside the visible strip without a clear overflow cue; this is a discoverability issue, not evidence that entries are absent. `permissions.js` filters navigation, while backend authorization remains authoritative. `App.jsx` keys sensitive pages by scope and authorization revision; pipeline data hooks use request cancellation/generation protection. Preserve those safeguards.

## Confirmed observations

- [Resource desktop](evidence/1366-resources.png): compact resource table and Resource Management sub-tabs exist. The Create Compute Instance button is inside the search/filter row (`UnifiedResourceManagement.jsx`), contrary to the approved page-header action placement. The row labeled `CONFIGURED` with `Enabled configuration` describes configuration, not verified monitoring health; the wording is easy to misread.
- [Access mobile](evidence/390-access.png): Create Department appears both in the upper action row and again within the department table controls. The four internal tabs and horizontal primary navigation consume several rows; primary navigation is clipped by viewport width. Departments are explicitly internal provider teams in this page.
- [Pipeline mobile](evidence/390-pipelines.png): six operational tabs are present, but the global navigation and wide list require horizontal exploration. The table has a scroll container; no page-wide horizontal overflow was measured at this viewport.
- [Compute mobile](evidence/390-compute.png): the operational view is present; a screenshot at one narrow width cannot establish all responsive states.
- The viewer Incident Correlation screenshot shows a permission notice. That is expected for a user lacking `incidents.view`, not a confirmed defect.

## Data and state boundaries

Resource Management owns customer Organizations, canonical resources, ETL integrations, collectors and configuration. Access Management owns internal employees/departments, roles, access assignments and restrictions. Operational views read configured resources and evidence. `CollectorControl.jsx` already models several independently configured methods and separates method kinds from logs/metrics/traces. Agent installation and future telemetry capabilities must not be inferred from its presence. Existing loading, empty, error and permission states exist in the inspected major views; missing states on every action were not proven. No backend endpoint absence is inferred from this audit.
