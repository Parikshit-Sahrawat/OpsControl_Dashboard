Cross-cutting design: `backend/app/main.py` mounts route families with `Depends(authorize_route)`; `security/http.py` handles session/worker identities; `security/scope.py` applies ORM scope. Frontend `api.js`, `resourceApi.js`, `controlPlane.js` and pipeline hooks are multiple domain clients, not proof of duplicate canonical ownership. The imported legacy pages (`ETLJobs.jsx`, `ResourceManagementV2.jsx`) require reachability checks before classifying as active workflows. Source presence alone is never counted as acceptance.

Method and limit: the tracked trees and route/model/test/workflow lists were enumerated; representative entry points, high-risk authorization/identity/recovery paths, Docker/Stage B scripts, migration head and backup tool were read. This is not line-by-line semantic proof of all 117 backend and 59 frontend files. The 26 capability rows above are families, not an assertion that every individual UI action or provider release was independently executed. Deeper target-specific code review is assigned in the [completion plan](../../planning/DEVELOPMENT_COMPLETION_MASTER_PLAN.md) before fixing or certifying those paths.
