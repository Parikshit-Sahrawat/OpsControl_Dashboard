All customer/environment/name/configuration-state filters issue real authenticated requests. URL values are revalidated against authorized inventory and never grant access. Name search is debounced; abort/sequence protection prevents stale inventory results. Global search is keyed by user/revision/operational organization/environment. Resource administration retains its **explicit independent customer filter**, indicated in the header; it does not silently inherit an operational scope.

Role adaptation uses the same backend/data/components. Viewer mutation controls are absent; backend denial is independently tested. Catalogue package creation/edit requires the existing platform-admin contract; it is disabled with an explanation otherwise. Scoped attachments require existing `templates.manage`. No permission catalog expansion.

Visible shell/resource controls: sidebar group expand/collapse/navigation; mobile drawer/Escape; real profile, Help, notifications and theme; timezone/density; resource search/selection; customer/environment/name/configuration filters, chips/reset/apply; refresh/pagination; resource detail/edit/create/collector configuration; committed template selection/version/overrides/save; saved effective preview; package create/edit/client validation/commit/history. Each uses existing behavior or a tested new handler. No mock health percentages, fake saved views, unsupported source replay, per-target rollout, restore button or workload-control controls were added. Desktop administration context substitutes an explicit inventory-context label for irrelevant global operational filters.

Advanced process/service/time-range/freshness filters and telemetry charts remain later-sprint capabilities. No Run/Retry/Stop/Terminate/Pentaho scheduler authority was added. Incident-management UI, ServiceNow, Kubernetes, SFTP and object-storage monitoring are excluded; no retired integration was reintroduced. This bounded sprint does not certify every unrelated legacy screen/control.
