## Exit rule and sequencing

Phase 1 is coding complete when every **approved implemented-scope** route, UI action, persistence path and negative authorization path has source and automated evidence; every remaining code gap is either fixed or explicitly deferred by the owner; CI is green on an immutable candidate; and the requested **80% critical backend coverage** is measured and passed without reducing scope. Independent manual UAT, installed-provider/Pentaho acceptance, representative performance, private-network trust and production DR are separate Phase 2/4 gates. Passing Phase 1 does not make the product production ready.

Sequence: (1) restore exact-main CI and 80% coverage evidence; (2) finish bounded UI/onboarding/API integrity; (3) close telemetry identity/delivery code gaps; (4) measure adapter/graph/query behavior; (5) only implement cluster, SLO, topology or certificate features after owner approves precise contracts; (6) repeat all affected regression and hand off exact SHA. Keep one branch per bounded change, reusable fixtures and an evidence table; do not create parallel systems.

Effort is an **estimate of active engineering hours**, excludes independent UAT and real infrastructure access, and is not a delivery promise. P0/P1/P2 entries below are development priorities, while `GATE` means verification-only until a defect reproduces.

## Program phase boundaries

**Phase 2 — Manual & Automated Testing:** test the immutable Phase 1 candidate in a dedicated UAT environment, record deployed SHA/image digests/schema revision and dated case-level results; run genuine Pentaho RT-001–RT-020, selected Windows/Linux/AWS/EKS/proxy/private-route compatibility only with approved real environments. Retest six historical Sprint 14R UAT failures and affected passes. Failed code behavior returns to Phase 1/3.

**Phase 3 — Improvements & Bug Fixes:** triage independently reproduced usability/performance defects, preserve baseline acceptance and run focused then full regression. New OC-IMP proposals require owner approval before entering this queue.

**Phase 4 — Deployment & Release:** verify seven release gates, 80% critical coverage, representative capacity, production CA/network trust, backup encryption/WAL/PITR/off-site custody, legal-hold retention, monthly restore and quarterly DR evidence against configurable RPO/RTO targets. No gate is certified by mock or controlled local evidence. Production is **NOT READY**.

The existing conditional Sprint 12–42 sequence in `docs/verification/sprint14r/ROADMAP_RECONCILIATION.md` remains a planning framework. Sprint 12–14/14R historical delivery credit is preserved. The next bounded development increment is DEV-01.1 plus DEV-06.1 measurement, followed by an exact-SHA gate rerun; later sprint numbers should not override dependency order.
