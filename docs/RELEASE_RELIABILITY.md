## P0 code resolutions

1. **Collector trust and secret handling.** Root cause: legacy API collection bypassed the stronger remote-worker egress boundary, and secret resolution read `os.environ` independently of `.env`-aware Settings. Impact: org administrators could drive a privileged local network request or production could accept local secret references. `backend/app/security/scope.py` protects API alongside infrastructure/Carte collector mutations; `backend/app/worker/collector_runtime.py` rejects production legacy API execution before secret resolution/network IO. `backend/app/worker/credentials.py` uses shared Settings. `backend/app/security/secret_refs.py` parses mixed-case and malformed URLs rather than checking a lower-case prefix. HTTP/HTTPS production collection uses the existing assigned remote-worker protocol; this does not certify customer firewall rules.
2. **Atomic mutation evidence and last administrator.** Root cause: middleware outcome audit ran after the resource transaction, and concurrent requests could both see another active administrator. Impact: committed changes without configuration audit or no active administrator. Scoped ORM flush appends sanitized CONFIG_MUTATION to the same transaction; rollback rolls back both. `backend/app/security/http.py` serializes last-admin updates with a PostgreSQL transaction lock. This complements the existing SQL append-only audit trigger; it does not make DB owners tamper-proof.
3. **Restore and retention.** Root cause: empty-database migration smoke tests did not prove recovery of evidence, while automatic cleanup covered only some local samples. Impact: recovery could lose rows/constraints and remote-worker evidence could grow indefinitely. `backend/scripts/database_backup.py` refuses overwrites, corrupted archives and nonempty restore targets. `database_integrity.py` compares every row, FK/check/unique/PK and schema head; only three known PostgreSQL-equivalent text CHECK deparses are canonicalized, with negative inserts tested. `backend/app/services/retention.py` deletes bounded batches using SKIP LOCKED and preserves correlation-linked metrics/logs. `prune_evidence.py` defaults to rollback. Audit, incident, collector-run and ETL histories stay retained until an approved archive/deletion policy exists.
4. **Deployment boundary.** Root cause: a migration-owner connection could run the service, and API headers did not protect separately served frontend assets. Impact: compromised runtime could change schema/audit or a spoofed proxy could bypass TLS requirements. `backend/app/security/deployment.py`, `backend/scripts/run_api.py`, `deploy/examples/restricted-database-roles.sql`, the Nginx template and CSP renderer provide explicit deployment controls. Production startup rejects privileged DB roles; the supported entrypoint validates bounded proxy IPs. Static CSP hashes the actual inline theme bootstrap. No public endpoint or real secret-provider identity is certified by the local lab.

## P1 code resolutions

1. **Execution bounds.** Root cause: async middleware performed synchronous SQL and scheduler task creation had no global per-process queue bound or cross-process local collector lock. Impact: blocked requests, duplicate evidence and pool exhaustion. Identity/outcome audit use Starlette's existing thread pool. Local collection owns one dedicated advisory-lock connection, checks due time inside the lock and releases/invalidate-on-error; pending tasks are bounded by configured concurrency and pool headroom. Notification polling runs independently. Kubernetes/boto reads have finite network timeouts. Providers may still need an overall deadline; local locks are not persisted lease/failover acceptance.
2. **Dashboard scale.** Root cause: fixed limits looked like complete inventories and service cards repeated queries per resource. Impact: operators miss resources and API cost grows linearly in service queries. `backend/app/api/operations.py` and `infrastructure.py` expose stable offset/limit/has_more/total metadata. `frontend/src/components/InventoryPager.jsx` and API/VM/incident pages expose previous/next controls and reset on scope/filter changes. Service prefetch performs four queries, with snapshots checked against existing behavior. `0022_runtime_query_indexes.py` supports local due selection/latest evidence. Summary counts labeled `summary_scope=page` remain page counts; filtering/search in inventory pages remain page-local. Do not describe them as complete fleet health.
3. **Input consistency.** Root cause: schemas accepted nonfinite thresholds and short user-create passwords rejected later in hashing. Impact: invalid rules or avoidable server errors. Monitoring/catalog validators reject NaN/infinity; user-create schema requires the existing 12-character policy. Functional formats remain unchanged.

## Deployment and maintenance runbook

- Create a separate migration owner and provision dedicated LOGIN identities through approved secret management. Apply `deploy/examples/restricted-database-roles.sql` as owner **after every migration**, then grant `opscontrol_app` to the runtime login and `opscontrol_maintenance` to the maintenance login. Never run the API with the owner. Revoking PUBLIC schema CREATE affects other apps sharing the DB: use a dedicated database.
- Configure `ENVIRONMENT=production`, an explicit HTTPS-only `CORS_ORIGINS`, a restricted `DATABASE_URL`, and exact ingress IPs/bounded CIDRs in `TRUSTED_PROXY_IPS`. Start with `python -m scripts.run_api` (or `backend/Dockerfile.runtime`). Keep port 8000 private; forwarding trust is not a firewall.
- Build the SPA with the intended same-origin HTTPS API base. Run `node frontend/scripts/render-production-nginx.mjs frontend/dist/index.html /private/path/nginx.conf http://api:8000`. Replace the example server name and add explicit unknown-host rejection for the target deployment. Mount TLS certificate/key and output config read-only. Renew certificates and regenerate CSP after every frontend build. Do not add `unsafe-inline` to script-src.
- Prefer assigned remote workers with explicit egress policy for production HTTP. Local API collection is intentionally unavailable in production. Cloud secret resolution requires a real read-only workload identity, approved ARN/region and rotation test; do not put tokens or DSNs into shell history/README.
- For backups provision private `PGSERVICEFILE` / passfile (0600), set nonsecret `PGSERVICE`, then `python -m scripts.database_backup backup /private/backup/populated.dump`. Restore into an **empty separate database** with the corresponding service: `python -m scripts.database_backup restore /private/backup/populated.dump`. Restore does not preserve ACLs/owners: reapply capabilities and verify non-owner startup. Encrypt/transfer archives using approved storage; never commit dumps or passwords.
- Restore a populated staging backup before each release, compare row/constraint fingerprints, exercise audit tamper negatives, and record recovery timing against agreed RTO/RPO. A small local timing is not a production recovery objective. Keep the old app/migration image and verified backup; index-only 0022 downgrade preserves rows. An interrupted concurrent index migration may leave valid or invalid partial indexes: inspect/drop only the four named indexes before retry; do not drop other indexes.
- Run `python -m scripts.prune_evidence --batch-size 1000` with maintenance identity first (dry run). Inspect counts, then add `--apply`; repeat bounded batches and schedule independently of collectors. Monitor backlog/failures, preserve correlated evidence. No historical audit trigger bypass or audit DELETE is allowed by this procedure.
